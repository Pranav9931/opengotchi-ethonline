OpenGotchi Jobs on Arc

ETHGlobal ETHOnline 2026 · Arc track · a voice-driven pet that hires and pays AI agents on Arc · repo github.com/Pranav9931/opengotchi-ethonline · written 13 Sept 2026
This repository is an extension of our flagship gotchiOS. gotchiOS is the ESP32-S3 pet operating system (wake word, voice rail, MQTT, MicroPython app runtime, AMOLED UI). Anyone can flash it onto their own ESP32 device from the open-source releases at https://github.com/opengotchi/gotchiOS-releases. Everything in this repository was written during the hackathon (4–13 Sept 2026) and runs on top of the stock firmware: no firmware code is modified or included.

1. What it does, in one sentence

Say "Jarvis, what's the weather in Berlin?" to the pet: the pet agent opens an ERC-8183 job on Arc, funds USDC escrow, a worker agent with an ERC-8004 onchain identity does the work and submits the deliverable hash, the pet verifies the hash, settles the USDC on Arc, records feedback on the worker's reputation, then speaks the answer and shows the receipt on its screen.

2. Was a contract deployed? Addresses

No contract of our own was deployed. The whole flow runs on the contracts Arc documents for its agentic economy, already live on Arc testnet (chain id 5042002, USDC is the native gas token). We are a client of those contracts, which is the point: the standards are the product.

3. The pipeline

Sequence of one request

  1. Wake word fires on the pet (or tap). arcvoice.py records via the firmware's background recorder with a live waveform and stops on silence.
  2. PCM is POSTed over the LAN to the agent; whisper.cpp transcribes in ~0.3 s.
  3. The planner maps the transcript to a worker skill and parameters with a confidence score.
  4. The policy engine approves or declines from live signals; declines are spoken and shown.
  5. Pet: createJob(provider=worker, evaluator=pet). Worker: setBudget. Pet: approve + fund (escrow). Worker: does the work, submit(keccak(result)). Pet: checks the hash, complete → USDC to worker. Pet: giveFeedback.
  6. Receipt (status, skill, job, price, tx, balance, today, result) is sent to the pet as a single MQTT message, then the answer is spoken through the pet's speaker via streamed TTS.

4. The device app: device/arcvoice.py

A single-file MicroPython app (~18 KB) that runs inside the stock gotchiOS app runtime. It is deployed over MQTT, not flashed: bun run deploy-app sends the file to og/d/<hash>/app/deploy with launch:true; the firmware stores it in /littlefs/apps/, so it also appears in the launcher for manual start. Before deploying, the script asks a running instance to exit cleanly (deploying over a live instance rebooted the pet twice during development).

Agent endpoint__AGENT_URL__ is substituted at deploy time with http://<PC LAN IP>:4010 (override with AGENT_PUBLIC_URL or a CLI argument). The pet and the PC must share a network.
Wake wordaudio.wake_ready()/wake_start()/wake_detected(): the firmware's on-device WakeNet "Jarvis" model. Armed at idle, disarmed while recording or speaking (the detector and recorder cannot share the mic), re-armed after. Tap is the fallback trigger.
Recordingaudio.rec_start(16000, 12, False) background recorder; the firmware delivers 8 kHz PCM16 into a ring. Energy VAD: noise floor learned in the first 300 ms, threshold = 3× floor + 350, stop after 800 ms of silence once speech was heard, minimum 1.2 s, maximum 7 s, give up after 4 s of nothing. Sent as POST /voice/stt with X-Sample-Rate: 8000.

5. The PC side: agent + worker

Processes

ProcessPortRole
bun run worker (worker/src)4030Registers an ERC-8004 identity on first start (stored in worker.json), serves the skill catalogue, sets budgets, does jobs, submits deliverable hashes.
bun run agent (agent/src)4010MQTT bridge to the pet, STT/TTS endpoints, planner, policy, Arc job lifecycle, ledger, control plane.

Speech

  • Speech-to-text: whisper.cpp (whisper-cli, Homebrew package whisper-cpp) with the ggml-base.en.bin model (148 MB, from huggingface.co/ggerganov/whisper.cpp), run locally with -nt -l en. About 200–350 ms per utterance on Apple Silicon. ffmpeg resamples the pet's 8 kHz audio to 16 kHz first.
  • Text-to-speech: macOS built-in say (system voice, override with SAY_VOICE) rendered at 16 kHz and converted by ffmpeg to raw signed 16-bit mono PCM, cached per sentence. On Linux, replace synthesize() in agent/src/voice.ts with piper or espeak-ng producing the same raw format.
  • Planner: Claude (claude-opus-5, structured outputs) when ANTHROPIC_API_KEY is set; a keyword planner otherwise. The hosted OpenGotchi voice API is not used at all.

Running on a completely new PC

# 1. tools (macOS; Linux: same minus `say`, see Speech above)
brew install node bun ffmpeg whisper-cpp
git clone https://github.com/Pranav9931/opengotchi-ethonline && cd opengotchi-ethonline
bun install
mkdir -p models && curl -L -o models/ggml-base.en.bin \
  https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.en.bin

# 2. configuration
cp .env.example .env
bun run wallet new              # prints AGENT_PRIVATE_KEY and WORKER_PRIVATE_KEY → paste into .env
# fund the agent address with Arc testnet USDC at https://faucet.circle.com (20 USDC is plenty)
bun run wallet fund-worker 3    # pet sends 3 USDC to the worker for gas
# .env: DEVICE_HASH=<pet hash>  GOTCHI_DEVICE_SECRET=<pet's provisioned secret>
#       WHISPER_MODEL=./models/ggml-base.en.bin   (ANTHROPIC_API_KEY optional)

# 3. run (two terminals), then push the app to the pet
bun run worker
bun run agent
bun run deploy-app              # substitutes this PC's LAN IP, exits any running copy, deploys + launches

The pet must run gotchiOS ≥ 0.0.421 (flash from github.com/opengotchi/gotchiOS-releases), be provisioned (it has a device hash and secret), and be on the same Wi-Fi as the PC. MQTT goes through mqtts://mqtt.opengotchi.com:8883; the PC logs in with the pet's hash as username and its secret as password, with a gotchi-bridge-* client id (the broker rejects agent-* ids). Without a device, curl -X POST localhost:4010/say -d '{"text":"…"}' drives the identical flow.

7. Honesty notes

  • Arc testnet only; Arc mainnet was not yet in Circle's stack during the hackathon. Switching is the viem chain object plus the mainnet registry addresses once published.
  • Wake word, mic, speaker and MQTT are gotchiOS features used through their public MicroPython APIs; the closed firmware source is not in this repo.
  • Worker skills use free public data. What is bought and sold is the job and its onchain settlement.
  • Wallets are self-managed keys for the demo; Arc's tutorials show the same flow with Circle developer-controlled wallets.
